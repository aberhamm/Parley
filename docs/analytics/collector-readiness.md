## Readiness schema1

`scripts/check-analytics-readiness.py` implements an exact-key stdlib schema.
Unknown fields, duplicate JSON keys, malformed types, nonfinite JSON numbers,
missing bindings and unsupported schema versions are refused. A receipt is a
regular nonsymlink file, at most64KiB. The checker only emits fixed status,
report-tier and blocker codes; it never echoes receipt contents or private paths.

Required exact expected manifest fields (top-level in both the receipt and
CLI inputs):

| Field / CLI flag | Required value |
| --- | --- |
| `contract_schema` / `--contract-schema` | Integer1, not a string or boolean |
| `relay_interface_schema` / `--relay-interface-schema` | Integer1 |
| `policy_sha256` / `--policy-sha256` | Lowercase SHA256 of the exact canonical007 policy artifact |
| `tracker_sha256` / `--tracker-sha256` | Lowercase SHA256 of the matching tracker bytes |
| `website_id` / `--website-id` | Canonical lowercase UUID of this exact website |
| `collector_version` / `--collector-version` | Exact version, not inferred from a mutable tag |
| `collector_build` / `--collector-build` | Exact independently checked collector build ID |
| `collector_image` / `--collector-image` | Immutable installed collector `sha256:` digest |
| `app_image` / `--app-image` | Immutable installed app image `sha256:` digest |
| `app_build` / `--app-build` | Lowercase SHA256 of independently extracted installed `/parley`, corroborated against the actual running immutable image without executable overrides; never a Version, source commit or environment label |

These are a point-in-time installed correspondence tuple, not a permanently
fixed app commit. Refresh readiness evidence after artifact/policy drift;006

Every evidence map key is required. The required keys are `owner`,
`capabilities`, `ingestion`, `policy_approval`, `site_access`, `expiry`,
`all_copies`, `restore`, `relay_artifact`, `installed_correspondence`,
`custody_phase` and `independent_review`. `identity` and `flow_reports` are
additional required keys whose values may be null for actions-only readiness.
A merged/unknown identity result does not prohibit action totals once ingestion
and custody are independently proved; it prohibits flow/unique-person claims.

Each non-null proof has exactly `ref`, `sha256`, `binding_sha256`, `checked_at`
and `scope`. `scope` is the literal `website`. `ref` is a private relative ID
of at most256characters/eight path components, with only letters, digits, dot,
underscore and hyphen inside each component, starting with a letter or digit.
Absolute paths, URLs, traversal, empty components and symlinks are refused.
Resolve IDs only inside required `--evidence-root`; referenced regular files
are at most1MiB. Proof bytes must exist and match lowercase `sha256`, with
fresh UTC `checked_at` under the same24-hour/five-minute bounds.

`binding_sha256` hashes UTF-8 JSON of **only the ten manifest fields above**,
with keys sorted, compact separators and no final newline (Python
`json.dumps(manifest, sort_keys=True, separators=(",", ":"))`). It binds the
proof index to the expected site, collector, policy, tracker and installed app
image/executable. It does not replace or regenerate the canonical policy.
Old proof indexes fail after any expected artifact/policy binding changes.

A reference and matching file hash prove only which bytes were supplied. They
do not prove the assertion inside those bytes, operator authority, signatures,
installed access or a completed purge. The accountable operator and DIFFERENT
reviewer must inspect the artifacts and independently corroborate them. The
checker deliberately does not parse unknown future229/230/231 proof schemas.
No sanitized receipt or self-asserted hash can substitute for that handoff.

## What the referenced private evidence must actually establish

- Owner/capabilities: exact current collector version/build/image/tracker;
  accountable role acceptance; supported APIs/features and native permission
  model. Distinguish the stock dedicated collector from the custom retired
  shared-target guard artifact.
- Ingestion: accepted fake-record readback through the actual validated007
  relay and exact tracker/collector, with a second untouched synthetic website.
  A bot-shaped HTTP200 or mock200 is not accepted-record proof.
- Access/policy:90-day raw-data approval, disabled public sharing, effective
  least-privilege dashboard/native/host/backup access and actual proxy identity
  inputs. Header minimization does not imply absence of derived metadata.
- Expiry/all copies/restore: independently validated229 expiry including event,
  property and reused session metadata; met deadlines; complete owned copies,
  exports, caches and historical snapshots under230; actual configuration-only
  recovery or expiry reconciliation before collector ingress/reports resume.
  A nominal30-day rotation does not authorize90days plus30days of retained data.
- Relay/correspondence: independently validated007 artifact, exact installed
  collector/app immutable images, independently extracted executable hash and
  running-container correspondence; no mutable executable mount override.
- Custody phase/review: actual231 collection-off installed staging receipts,
  including non-ready publication/wait/exit/DBwriter-drain sequencing, and the
  independent review of the complete bound bundle. Plans alone are not proofs.
- Flow tier only: two separate same-User-Agent browser contexts behind the
  gateway-equivalent boundary, plus actual ordering/maximum60minutes between
  consecutive steps and property-selection semantics. Merged/unknown results
  keep this tier unavailable; never add real IPs or distinct IDs to repair it.
