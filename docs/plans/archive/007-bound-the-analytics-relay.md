## Plain-English Summary

Keep the native analytics collector private while letting the browser send only the small, reviewed set of Scrum Pro usage signals. The application must stop accepting analytics during maintenance or whenever current custody proof is absent, without interrupting meetings or sign-in.

**What changes in the code:** add two bounded public analytics handlers to the existing Go binary, a single shared policy artifact consumed by the browser and relay, and a short-lived local admission-file check. Replace the dedicated gateway's direct connection to the old shared collector only at the separately verified cutover. No extra relay service or dependency is introduced.

Matthew directly authorized the scoped analytics work, reviewed plans instead of an issue, independent validation, integration and deployment after checks pass. Parent owns the exact detached worktree and integration. This is an unapproved plan, not implementation or live acceptance.

## Requirements

- [ ] Only `GET /a/script.js` and `POST /a/api/send` can reach the fixed dedicated collector paths `/script.js` and `/api/send`. The `/a` group's unknown paths/methods refuse; no native admin, identify, pixel/link, arbitrary path or public collector bypass is exposed. Disabled configuration returns a fixed refusal and never uses the SPA as an upstream.
- [ ] The relay reads no session cookie, principal, account, membership or app database. It neither mints nor forwards identity. Mount inside the ordinary security-header profile and outside `/api` principal middleware. Apply explicit same-origin/non-cross-site, JSON, host and resource controls. Reject nonempty Authorization on `/a` without token resolution, and classify the exact signed-link, embedded and tenancy routes in their real tables; cookies are ignored, never forwarded. An embedded browser is not inferred from a cookie: frontend frame suppression and explicit bearer refusal must be independently tested.
- [ ] A valid request is exactly the matching 3.0.3 envelope described in the interface below. Reject duplicate JSON keys, multiple JSON values, unknown selectors/keys, identify/id/timestamp/IP/User-Agent overrides, mismatched website/hostname, unapproved strings and data shapes. Construct a fresh output from the canonical finite policy; never forward the original body. Ignore incoming cache headers rather than adopting them, and never return a native cache token.
- [ ] One canonical, versioned JSON policy becomes the runtime source of event names, properties/enums, fixed page categories, website/hostname and version/hash pins. Browser projection and generated embedded Go policy consume it. Keep the tested public TypeScript API stable; generated-copy/check tests must detect drift, not merely compare two separately handwritten lists.
- [ ] Both handlers require a fresh bound runtime admission file. Missing, stale, malformed, symlinked/unsafe, unknown-field, mismatched or non-ready state means no upstream request. Read the current file on every request; no sticky cached ready state. A locally valid receipt is an operator proof input, not proof generated by the relay itself. Preserve plan005's separate 24-hour rollout receipt and plan006's final artifact binding.
- [ ] Optional analytics failure never prevents app startup, health/readiness, auth or meeting operations. No app DB, persistent queue, retries or per-person/IP state. Resource caps are per process and disclosed: 16KiB request, 256KiB script, 8 concurrent requests, 20 requests/second with burst40, 5-second absolute operation budget, 2-second body-read budget; no unbounded waits. Use existing stdlib facilities, not a new rate-limit dependency.
- [ ] Default off. Main validates the all-or-nothing optional environment, maps it through a real api.Options field, and tests a router built from that mapping. Add every environment key to configuration.mdx and Helm values, plus .env.example and deployment docs. No silent omission from main or route tables.
- [ ] Add red-first route, projection, receipt, transport, wiring and negative tests plus mutations for every new boundary. Different agent validation precedes completion. Production collection and Caddy cutover remain blocked until Homelab228–231 and app005/006 acceptance; do not promote evidence merely because local tests pass.

### Exact cross-repo interface

The full operator interface is also recorded privately at `relay-interface.md`. Freeze it before either producer or consumer code; changes require the same two owners and independent recheck.

- Public addresses unchanged: `/a/script.js`, `/a/api/send`. The dedicated gateway must pass these to `public-app:8080`, not directly to a native collector. Native collector/DB has no public port; the Go app joins a collector-only ingress network, while Postgres remains on a separate internal backend network.
- Optional environment: `ANALYTICS_RELAY_URL` is empty by default; the only production value is `http://scrum-analytics-collector:3000`. `ANALYTICS_RELAY_STATE_DIR` is empty by default; enabling requires an absolute private directory, mounted read-only at `/run/parley-analytics` in the app. No credentials or arbitrary URL/path/query/userinfo are accepted in the upstream. Tests inject an httptest upstream through the typed handler config, never weaken production validation.
- Mount the WHOLE state directory read-only, not one file: the producer atomically replaces `admission.json`, and a file bind mount can retain the old inode. Parent dirs and file have verified operator-write/app-read-only access. Reject links and nonregular/overlarge files; inspect the opened descriptor and validate the complete JSON with no trailing data/duplicate keys. Cap at8KiB. Never log its body.
- Runtime file schema1 fields: `schema`, `generation`(nonnegative integer), `state`(`ready`, `maintenance`, `blocked`, `retention_failed`), `checked_at`, `valid_until`(UTC RFC3339), `contract_schema`(1), `policy_sha256`, `website_id`, `collector_version`, `collector_image`, `tracker_sha256`, `app_build`. Unknown fields/states fail closed. Ready requires exact compiled policy/site/collector/tracker pins and `app_build` as the lowercase 64-hex SHA256 of the actual delivered executable computed at startup; it is NOT `api.Options.Version`, an environment label, source commit or container tag. Human Version remains separate; dev/unstamped production enablement still refuses.
- Artifact identity producer/consumer: add a stdlib startup helper that opens the running executable itself (`/proc/self/exe` on production Linux), verifies a regular file, hashes its bytes with SHA256 and closes it; do not hash a replaceable pathname, tag or externally supplied digest. For supported local non-Linux tests use an injected opener/fixture; non-Linux startup may use os.Executable only under verified immutable executable custody, otherwise analytics is unavailable. The binary runs from the immutable image filesystem without a writable executable mount; this trusted runtime custody is a deployment prerequisite, not a new security claim. Read/hash failure, empty/malformed identity or unsupported custody disables BOTH analytics handlers only, leaving app startup/auth/meetings/health intact. Compute fresh on each process start, never persist/reuse a prior process fingerprint. The producer records the immutable installed image digest and independently extracts/hashes that image's delivered `/parley`, verifies the running container uses that exact image and no executable override, then sets `app_build` to that executable hash. Same semantic Version cannot authorize another binary. Native collector_image and the app image correspondence proof remain distinct; app_build is the exact runtime comparison input. No existing helper is claimed: these main/helper/Options paths are new scoped implementation.
- Timing: ready heartbeat at most every30seconds; validity at most60seconds from checked_at, future skew at most5seconds, and valid_until must still be in the future. The producer may only write ready after its actual retention, copy-custody and installed-artifact gates pass. This is a short-lived request-admission lease, NOT plan005's rollout-readiness schema or an automatic compliance assertion.
- Snapshot linearization: each request starts its absolute monotonic 5-second deadline at handler entry, BEFORE parsing/opening. Successful opening of the current admission-file descriptor acquires its per-request snapshot; validate/read that same descriptor. Snapshots acquired after non-ready publication refuse. A descriptor acquired before publication may still contain ready after rename, but can finish ONLY within its original deadline, including parsing, receipt reading/validation, scheduling, hashing and upstream I/O. Check cancellation before forwarding and use the same remaining deadline throughout; no queue, retry, readiness cache or detached continuation extends it. Do not promise zero admission/forwarding at the instant of rename.
- For maintenance the producer first atomically publishes a non-ready generation, waits at least6seconds measured from completion of atomic publication (longer than the entire lifetime of any prior snapshot operation), then stops the dedicated collector and verifies its process exit AND database writer drain before any purge. No cached relay readiness or automatic HTTP retries may extend that bound. The collector remains unavailable until purge/status/custody checks succeed; a failed or missed deletion deadline is `retention_failed`, not compliant deletion merely because ingress is shut.
- `GET` accepts no query and reads only fixed `/script.js`; a 2xx body is size-bounded and must match the pinned tracker SHA256 before any bytes are served. Preserve security headers; do not relay Set-Cookie, native headers or error bodies. Invalid hash/redirect/status/timeouts are fixed503/no-cache.
- `POST` accepts one application/json envelope: `{ "type":"event", "payload": { "website": <fixed UUID>, "hostname":"scrum.matthew.systems", "url":<fixed page category>, "title":"Scrum Pro", "referrer":"" [, "name":<approved event>, "data":<schema1 approved primitives>] } }`. Page-only bodies have no data/name. No dynamic IDs, query, fragment, titles, raw errors, arbitrary nested data, website/link/pixel conflict or backdating. Match the saved native3.0.3 browser fixture, not latest docs.
- Forward only Content-Type and a fixed nonidentifying User-Agent plus the fixed upstream Host. Do not forward cookies, Authorization, Origin/Referer, forwarding/client IP, native cache, arbitrary incoming headers or query. No redirects or transport retries. Upstream success becomes200 `{}`; discard cache token/body. Other outcomes become fixed errors with bounded status behavior. Header DNT1 refuses collection without forwarding. Normal input cookies are ignored rather than treated as authentication.
- Request body reading is actually time-bounded, not merely a context around a potentially blocking decode; use the server response-controller read deadline and real slow-client tests. The absolute5second request lifetime covers parsing, admission and upstream. Saturation fails promptly. No app database or per-client/IP counters.
